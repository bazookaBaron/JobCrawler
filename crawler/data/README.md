# data/

Trimmed from upstream jobseek (`apps/crawler/data/`). Only two files are used
by this fork's pipeline (`src/pgpipe/`):

| file | rows | schema |
|---|---|---|
| `companies.csv` | ~500 | `slug,name,website,logo_url,icon_url,logo_type,industry,employee_count_range,founded_year,extras` (upstream schema, unchanged) |
| `boards.csv` | ~516 | `company_slug,board_slug,board_url,monitor_type,monitor_config,scraper_type,scraper_config` (upstream schema; `scraper_*` columns are ignored — this fork uses rich monitors only) |

`jobs sync` loads `slug,name,website,industry` into `crawler.company` and
`company_slug,board_slug,board_url,monitor_type,monitor_config` into
`crawler.job_board`. Everything else is ignored.

Regenerate from a fresh upstream clone with `tools/trim_csvs.py`
(keeps only companies whose every board uses a rich, non-browser HTTP monitor).

Upstream's `company_descriptions.csv` and `images/` were **removed** — the
jobs board does no taxonomy resolution and stores no descriptions.

### Market report (`src/report/`)

The daily market report uses its own, much larger board list plus upstream's
taxonomies. All regenerated by `tools/build_report_data.py <upstream clone>`:

| file | used for |
|---|---|
| `report/companies.csv`, `report/boards.csv` | every upstream board readable over plain HTTP with a rich monitor (~4.7k companies / ~5.4k boards, all industries) |
| `occupations.csv`, `occupation_domains.csv`, `seniority.csv`, `technologies.csv`, `industries.csv` | upstream taxonomies, read by `src/core/*_resolve.py` |
| `report/geo_countries.csv`, `report/geo_cities.csv` | offline location resolution (GeoNames, CC-BY 4.0, cities >= 15k people) |

`jobs sync` never reads any of these.
